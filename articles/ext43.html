1. Gitのコミット時、「なんてコミットメッセージを書けばいいか分からない」と手が止まっていませんか？

1-1. 「fix bug」「update」などの適当なコミットで、チームメンバーや未来の自分から呆れられる絶望

「コードの修正が完了し、いざコミットしようとした瞬間、メッセージ入力欄の前で手がピタッと止まってしまう…」 「英語で書くべきか日本語で書くべきか悩み、結局面倒になって『update』や『fix』『修正』といった雑なメッセージで送信してしまった…」 Webエンジニアやチーム開発を行なうプログラマーなら、誰しも一度はこのコミットメッセージ作成の手間と悩みを経験しているはずです。

1-2. チームの規約（Conventional Commits）を意識しながらメッセージを考える時間ロス

多くの開発チームでは、「feat:（新機能）」「fix:（バグ修正）」「refactor:（リファクタリング）」「docs:（ドキュメント更新）」といった世界的標準フォーマット（Conventional Commits）が推奨されています。 しかし、変更したコード差分（Diff）を見ながら、「これはrefactorなのかfixなのか？」を都度考えて日本語で文章化するのは地味に手間がかかります。

1-3. ポップアップでの手動組み立て ＋ GitHubのPR作成画面での自動反映

「日本語コミットメッセージ作成」は、そんなコミットメッセージ作成の悩みを軽くするChrome拡張機能です。 拡張機能アイコンをクリックして開くポップアップ画面の中で、コミットタイプ（feat/fix/refactorなど）をカードから選び、影響範囲や変更内容を入力すると、プレフィックス付きの日本語コミットメッセージがその場でプレビュー生成されます。 git diffの出力をテキストエリアに貼り付けて解析ボタンを押せば、変更されたファイル名・追加/削除行数・キーワードなどからタイプと件名を自動推測することもできます。 さらに、GitHubのPull Request作成画面（compareページ）を開いていると画面右下にボタンが表示され、そこに表示されている差分を読み取ってPRのタイトル・説明欄へ自動反映することもできます（GitLab・Bitbucketや、その他のコミット画面には対応していません）。

2. 実際にできること

2-1. コミットタイプの手動選択 or git diffからのルールベース推測

8種類のコミットタイプ（feat/fix/refactor/docs/style/test/chore/perf）をカードから手動で選べるほか、「🔍 git diff 差分から自動生成」欄にgit diffの出力テキストを貼り付けて解析ボタンを押すと、変更ファイルの拡張子・追加/削除行数・「error」「fix」「bug」などのキーワードの有無から、あらかじめ決められたルールでタイプと件名の候補を組み立てます（AIやLLMによる文章生成ではなく、拡張機能内で完結するルールベースの解析です）。

2-2. GitHubのPR作成画面(compareページ)での自動反映

GitHub上で https://github.com/<owner>/<repo>/compare/... のようなPull Request作成画面を開くと、画面右下に「💮 コミットメッセージを生成」ボタンが表示されます。クリックすると、その画面に表示されている差分（追加・削除行数やファイル名）を読み取り、上記と同じルールベースのロジックでタイトルと説明文を組み立てて、GitHubのPRタイトル・説明欄に自動で入力します。同時に同じ内容をクリップボードにもコピーするため、万が一入力欄への反映がうまくいかない場合でも、手動で貼り付けてご利用いただけます。

2-3. 4種類のメッセージ形式から選択 ＆ ワンクリックでクリップボードにコピー

ポップアップでは「絵文字＋英語Prefix」「和風Prefix（【新機能】等）」「Prefixなし（日本語のみ）」「英語Prefixのみ」の4形式から選んでプレビューを切り替えられ、「クリップボードにコピー」ボタンで1タップコピーできます。ターミナルなど、GitHub以外の実際にコミットする画面へは、ご自身でペーストしてご利用ください。

3. 使い方の具体例

3-1. 【シナリオA】GitHubでPull Requestを作成するとき

GitHub上でPull Requestの作成画面（compareページ）を開くと、右下に「💮 コミットメッセージを生成」ボタンが表示されます。クリックすると、表示されている差分からタイトルと説明文の候補が自動的にPRフォームへ入力されます。あくまでルールベースの推測なので、送信前に内容を確認し、必要に応じて手直ししてください。

3-2. 【シナリオB】ポップアップでコミットタイプと件名を手入力する場合

拡張機能アイコンをクリックしてポップアップを開き、該当するタイプのカード（例: fix）をクリック。影響範囲（scope）と変更内容（subject）を入力すると、「🐛 fix(auth): ログインエラー時のリダイレクトを修正」のようなメッセージが即座にプレビューされます。

3-3. 【シナリオC】英語が得意でないエンジニアや、学習中のプログラミング初学者のとき

「コミットメッセージは英語で格好良く書かなきゃ…」という悩みを、和風Prefix形式（【新機能】【バグ修正】等）を使うことで軽減できます。

4. よくある質問（Q&A）

Q1. 差分の内容が外部のサーバーに送信されませんか？

A. 送信されません。 git diffテキストの解析も、GitHub compareページ上の差分の読み取りも、すべてブラウザのローカル環境で完結する処理で、外部のAPIやサーバーへの通信は一切行いません。

Q2. チーム独自のコミット規約（例: [JIRA-123] などのチケット番号付与）に対応できますか？

A. 現状では対応していません。 用意されている4種類のメッセージ形式から選ぶ仕様になっており、チケット番号などを組み込む独自テンプレート機能はありません。件名欄に手入力で追記してご利用ください。

Q3. GitHub以外のWebサービス（GitLabやBitbucket等）でも使えますか？

A. 現状はGitHubのPR作成画面のみです。 GitLab・Bitbucketの画面や、GitHub上のファイル直接編集時のコミット画面などには対応していません。それ以外の場面では、ポップアップを開いて手動でご利用ください。

Q4. 生成された日本語メッセージを少し手直しすることはできますか？

A. もちろん可能です。 ポップアップの件名・詳細説明の入力欄、GitHub上のPRタイトル・説明欄とも、自動入力後にいつでも自由に編集できます。

■ 使い方（簡単3ステップ）

  1. GitHubでPull Requestの作成画面を開く（またはポップアップを開く）。
  2. 右下の「コミットメッセージを生成」ボタンを押すか、ポップアップでコミットタイプのカードを選ぶ／git diffの出力を貼り付けて解析する。
  3. 内容を確認し、そのままコミット・PR作成、または「クリップボードにコピー」ボタンで貼り付けて完了！

差分の解析およびメッセージフォーマットの組み立ては、すべてお使いのブラウザ内部で行われます。外部のサーバーへ送信されることは一切ありません。
